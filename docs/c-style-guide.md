# C Style Guide

Guidelines for writing matching C in this decompilation project. The original
binary was compiled with a PSY-Q SDK version of GCC. We use GCC 2.8.1-psx from
decompals/old-gcc, which is the same compiler family but makes some different
optimization and register allocation choices. This guide documents the known
differences and how to handle them.

## General Rules

- Write the simplest, most natural C first. Only add workarounds after
  confirming a mismatch with `npx tsx tools/diffFunc.ts <func>`.
- Struct types for globals go in `include/globals_override.h`, not in source
  files.
- `register __asm__` is acceptable as a last resort when no C reformulation
  fixes a register allocation mismatch. Silent Hill's decomp uses it in 3
  files for the same reason.

## Scheduling Barriers

GCC's instruction scheduler reorders independent instructions to hide pipeline
stalls. The original PSY-Q toolchain did not always do this. When the scheduler
produces a different instruction order, insert a zero-cost barrier:

```c
__asm__ volatile("" : "=r"(var) : "0"(var));
```

This emits zero instructions. It tells GCC that `var` is consumed and produced
at that point, preventing it from reordering instructions across the barrier.

### Pattern: Interleaved pointer loads

When loading two absolute-addressed pointers, GCC interleaves the `lui+lw`
pairs to fill the pipeline stall after `lui`:

```
lui v0, hi(A)     <- GCC groups the two lui's together
lui v1, hi(B)
lw  v0, lo(A)(v0)
lw  v1, lo(B)(v1)
```

The original binary has them sequential:

```
lui v0, hi(A)
lw  v0, lo(A)(v0)
lui v1, hi(B)
lw  v1, lo(B)(v1)
```

Fix by inserting a barrier after the first load:

```c
// Natural C (mismatches due to interleaving):
Foo *a = GLOBAL_A[0];
Foo *b = GLOBAL_B[0];

// With barrier (matches):
Foo *a = GLOBAL_A[0];
__asm__ volatile("" : "=r"(a) : "0"(a));
Foo *b = GLOBAL_B[0];
```

Only needed for absolute-addressed symbols (outside GP range, accessed via
`lui+lw`). GP-relative loads are single instructions and don't get interleaved.

See `src/func_80013AA4.c` for a real example.

### Pattern: Address load before ALU op

When indexing into an array, GCC emits the address load (`la`) before an
independent shift:

```
la   v0, SYMBOL
sll  a0, a0, 2
addu a0, a0, v0
```

The original has the shift first:

```
sll  a0, a0, 2
addiu v0, gp, offset
addu a0, a0, v0
```

The natural C is a simple array store like `(&SYM)[idx] = val`. The workaround
computes the index shift first and inserts a barrier before the address load:

```c
// Natural C (mismatches due to la/sll order):
(&D_8005E4C8)[arg0] = arg1;

// With barrier (matches):
arg0 <<= 2;
__asm__ volatile("" : "=r"(arg0) : "0"(arg0));
base = &D_8005E4C8;
*(s32*)((char*)base + arg0) = arg1;
```

See `src/func_8001B4D0.c` for a real example.

## Register Assignment

GCC's register allocator sometimes picks different registers than the original
compiler. For example, GCC may reuse `$v0` for two constants where the original
used both `$v1` and `$v0`.

When no C reformulation fixes it, constrain variables to specific registers:

```c
register s16 a __asm__("v1") = -1;
register s16 b __asm__("v0") = -3;
```

Before resorting to this, try:
- Changing variable declaration order
- Using different types (`s16` vs `s32`)
- Restructuring the computation

See `src/func_8001ACA0.c` for a real example.

## Globals

### GP-relative vs absolute addressing

With `-G8`, the compiler and assembler use GP-relative addressing (single
`lw`/`sw` instruction) for extern symbols declared as <= 8 bytes. Symbols
declared as > 8 bytes use absolute addressing (`lui` + `lw`/`sw`).

GP-relative symbols are declared as plain externs in `globals.h`:

```c
extern s32 D_8005E394;
```

Absolute-addressed symbols use the `_D_` pattern — an array large enough to
exceed 8 bytes, with `__asm__` to emit the real symbol name:

```c
extern s32 _D_80061DE8[3] __asm__("D_80061DE8");
#define D_80061DE8 (*((s32*)_D_80061DE8))
```

Both patterns are auto-generated by `classifyGlobals.ts` based on how the
original binary accesses each symbol.

### Struct overrides

`classifyGlobals.ts` generates all globals as scalars (`s32`, `u16`, etc.).
When a global is actually a struct, define its real type in
`include/globals_override.h`. The auto-generator skips any symbol that appears
in that file.

For absolute-addressed structs, declare as a single-element array (the struct
itself must be > 8 bytes to trigger absolute addressing):

```c
// include/globals_override.h
struct UnkStruct_D_80061DE8 {
    s32 unk0, unk4, unk8;
    char pad[0xC];
    s32 unk18, unk1C;
};
extern struct UnkStruct_D_80061DE8 _D_80061DE8[1] __asm__("D_80061DE8");
#define D_80061DE8 (*((struct UnkStruct_D_80061DE8*)_D_80061DE8))
```

For GP-relative structs (<= 8 bytes), use a plain extern:

```c
extern struct SmallStruct D_8005XXXX;
```

Do not use `#undef` in source files to override `globals.h`. Use the override
file instead.

## BREAK Macro

Use `M2C_BREAK(n)` or `BREAK(n)` from `common.h`:

```c
s32 func(void) {
    M2C_BREAK(1);
    return 1;
}
```

The macro uses `"break %0" :: "n"((n) * 1024)` to emit a single-operand
`break` instruction. This is needed because upstream maspsx cannot parse the
two-operand `break N, 0` form that GCC would otherwise emit from inline asm.
