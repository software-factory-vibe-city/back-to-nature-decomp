## 1. Why this function was singled out

It is the only function in the real undecompiled backlog that trips the
register-saturation signature described in
`notes/research/func_80012598.md` §3.6 and §4:

```
distinct allocatable registers >= 23  AND  max base-copy fan-out >= 5
```

Measured over the 104 live, non-handwritten, undecompiled functions in
`build/callGraph.json`: **one hit, this function.** (Scanning the raw
`build/functions/*.s` set instead gives a second hit, `_padChkRC2wait`, which is
linked PSY-Q library code and absent from the call graph — not a target.)

It is also one of four functions in the whole binary that an opcode-shingle
comparison (K=10) reports as >=30% covered by an already-matched function:

```
func_80015A34   ~ func_80015AAC   100%   (30 insns)
func_800121D4   ~ func_800120C8    93%   (49 insns)
func_8001231C   ~ func_80012598    68%   (159 insns)
SsSeqOpen       ~ func_80021E60     66%   (164 insns)
```

Both signals point the same way, from target bytes alone, with no compile.

## 2. What it is

The same graphics-heap carve and double-buffer / ordering-table initialisation
as `func_80012598`, for a second configuration. Read the field map and the pool
layout from `notes/research/func_80012598.md` §1 — every offset and every
constant carries over except the two values in §3.

Shape (from `psx_triage` and the disassembly):

- frame `0x40` = args `0x10` + vars `0x8` + saves `0x28` (`$s0`-`$s7`, `$fp`,
  `$ra`) — **identical to `func_80012598`**
- no proven parameters, return type undetermined, no recorded callers
- `memset((void *)0x801BE1B0, 0, 0x3EE50)` then `D_8005E3B0 = 0x801BE1B0`
- **one** loop: the 2-iteration per-context init, `$fp` countdown with `bgez`
  (a `check_dbra_loop` reversal of a count-up `for`)
- then `jal func_8001E160` — where `func_80012598` *inlines* that same body as
  its second loop. `func_8001E160` is already matched (`src/func_8001E160.c`).

## 3. The six deltas from `func_80012598` — this is the whole job

Copy `src/func_80012598.c` and change exactly this:

1. **`D_8005E3BC` / `D_8005E3B8` get `0x801F7000`**, not `0x801FCFF8`.
   (`0x8001236C`/`0x80012370`, stored at `0x800123C0`/`0x800123C4`.)
2. **The work-area stride is `0x2EE0`**, not `0x5EDC`. Both places: the spilled
   accumulator increment (`0x800123FC addiu $v0, $v0, 0x2EE0`) and the length
   written to `0x128` (`0x80012548`, sourced from `addiu $v0, $zero, 0x2EE0`).
   The `0x33090` pool offset and the `addu $a2, $s7, $a2` base add are unchanged.
3. **Replace the entire second loop with a call**: `func_8001E160();`. Declare
   it — it is `void func_8001E160(void)`; see `src/func_8001E160.c`. An
   undeclared callee would poison `$v0` after the call
   (`notes/research/func_80012598.md` cites the general rule; the mechanism is
   in the `func_80022738` retro).
4. **Rotate the pins.** `func_80012598` and this function assign the same roles
   to different registers. Change only the `asm("$n")` numbers:

   | role | `func_80012598` | `func_8001231C` |
   |---|---|---|
   | `&D_8005E5E8` | `$s0` (16) | **`$t8` (24)** |
   | byte pointer (`0x16`-`0x1B`, `0x130`) | `$s1` (17) | **`$t9` (25)** |
   | pool cursor p0 `0x801BE1B0` +0x100 | `$s2` (18) | **`$s0` (16)** |
   | pool cursor p1 `0x801BE3B0` +0x40 | `$t8` (24) | **`$s1` (17)** |
   | pool cursor p2 `0x801BE430` +8 | `$t9` (25) | **`$s2` (18)** |
   | OT cursor `0x801BE440` +0x2000 | `$s3` (19) | `$s3` (19) |
   | VRAM cursor `0x801C2440` +`$s6` | `$s4` (20) | `$s4` (20) |
   | constant `1` | `$s5` (21) | `$s5` (21) |
   | constant `0x17700` | `$s6` (22) | `$s6` (22) |
   | constant `0x801BE1B0` | `$s7` (23) | `$s7` (23) |
   | byte offset (`+= 0x134`) | `$t7` (15) | `$t7` (15) |
   | counter | `$fp` (30) | `$fp` (30) |
   | `rV0`/`rV1`/`rA0`/`rA1`/`rA3`/`rT6`/`temp_a2` | `$2/$3/$4/$5/$7/$14/$6` | unchanged |

5. **The base is formed as `addu $a0, $t8, $t7`** — base register first, offset
   second (`0x800123D8`). `func_80012598` has `addu $a0, $s0, $t7`, same order,
   so the existing source line is already right; just make sure the rotation in
   (4) does not flip it.
6. **The symbol load is `lui $v0, %hi` / `addiu $t8, $v0, %lo`**
   (`0x80012380`/`0x80012384`), then `addu $t9, $t8, $zero`. This is the same
   two-instruction split-address form that forced the hand-written `lui`/`addiu`
   pair in `func_80012598` (see `notes/research/func_80012598.md` §6 item 4) —
   reuse that asm verbatim, changing only the output register.

Everything else — the memset, `D_8005E3B0`, the store order, the chained
`ot->offset = ot->point = 0` assignments, the `0x134` stride, the spill at
`0x10($sp)`, the `COPY` macro and its call sites, the two zero-instruction
ordering barriers — should carry over unchanged.

## 4. Verification recipe

```

npx tsx tools/agent/diffFunc.ts func_8001231C --bytes     # the actual verdict

npx tsx tools/agent/sourcePolicy.ts func_8001231C
```

**Use `--bytes` or `make check` as the verdict, not `--src`.** `--src` reported
`VERDICT: MISMATCH -- 0 word(s) differ` at `Match: 206/209` on `func_80012598`
while the linked binary differed in **25** words: `0 differing` with
`same < total` means every instruction is present and correct but some are
*displaced*, and a rotated block shifts many addresses while differing in no
compared pair. See `notes/research/func_80012598.md` §6 "Traps worth knowing"
and the project's masked-diff note.

If the source ends up needing the same policy exception, add
`"func_8001231c": ["register-asm", "embedded-asm"]` to
`.pi/autodecomp.json` `sourcePolicy.allowlist` **in the same change**, with the
evidence comment in the source header — and only once it actually matches. The
skill's rule is that an allowlist entry asserts the exempted construct is the
right answer for that function; being stuck is not that assertion.

## 5. Traps, all already paid for

- **The base-address copies are reload rematerialisations, not CSE artifacts.**
  `lreg` holds 4 reg-to-reg sets, `greg` 18. They cost the original nothing
  (one-instruction live ranges, spread later by `sched2`) while every copy a C
  reconstruction creates holds a register. Do not try to manufacture them from
  source pointer variables — that is what consumed two sessions.
  `notes/research/func_80012598.md` §3.1.
- **Peak base-equal register overlap is the budget.** Measure the target's; if
  yours is higher you are one register short per extra copy, exactly linearly.
  §4.1.
- **A `volatile` asm is a store barrier**, and an asm with no outputs is
  implicitly volatile. The placement of `__asm__("" : : "m"(sp10))` relative to
  the two `%gp_rel` stores decides whether they sit at the end of the preheader
  (correct) or 19 instructions early (25 linked bytes wrong). §6 item 5.
- **Use the non-volatile `"=r"/"0"` form for pure ordering.** Using a volatile
  asm to pin a constant re-hoisted the `%gp_rel` stores and made things worse.
- **Sweeping a respell's normalisation constant is one experiment, not nine.**
  Nine offsets compiled byte-identically; `cse2`'s `simplify_plus_minus` erases
  the constant. §4.3.
- **Refuted, with measurements, do not repeat**: typed struct `ARRAY_REF` form,
  two-step respell from `base`, one-instruction respells applied in bulk,
  init-statement reordering in the preheader, late birth of the cluster views,
  merging stores onto the shared web, a single transparent base pointer (which
  is *semantically* wrong — GCC dead-codes the `0x110`/`0x114`/`0x120` stores
  that the second phase overwrites). §4.3, §4.6.

## 6. Cost expectation and stop rule

`func_80012598` took two sessions; the first ended `escalation-exhausted` at 61
differing words. This one should not, because the field map, the store order,
the sibling call, the register roles and the trap list are all in hand and the
second phase is a call rather than an inlined loop.

Stop rule, so it cannot repeat the first session's failure mode: require
**instruction-count parity and opcode-multiset parity together**. If both are
not reached, stop and file the diff signature rather than escalating model tier
— the first session's 144 -> 106 -> 61 descent was entirely inside an
instruction-count family that could never reach the target. Count parity must be
read with the assembler delay-slot caveat that
`psx_search_residual_source_space` prints (the target's 209th word in
`func_80012598` was an assembler load-delay fill, so 208 was the cc1 count).
