## 1. What the function is

A graphics-heap carve plus double-buffer / ordering-table initialiser. Nothing
in the previous notes identified it, which is why 40 stores looked like an
arbitrary permutation problem instead of ordinary source.

`D_8005E5E8[2]` is the double-buffered render context, stride `0x134`. Field
map — the DRAWENV/DISPENV rows are corroborated by sibling call sites, the rest
by the store values themselves:

| Offset | Meaning | Evidence |
|---|---|---|
| `0x000` | `DRAWENV draw` (0x5C) | `func_80011370` calls `SetDefDrawEnv` on `+0x000` and `+0x134` |
| `0x016`–`0x01B` | `draw.dtd/dfe/isbg = 1`, `draw.r0/g0/b0 = 0` | the six `sb`; exact DRAWENV field offsets |
| `0x05C` | `DISPENV disp` (0x14) | `func_80011370` calls `SetDefDispEnv` on `+0x05C` and `+0x190` |
| `0x084` | `GsOT ot[4]` | libgs `GsOT` is exactly `0x14`: `{length, org, offset, point, tag}` |
| `0x0D8` | `GsOT_TAG *org[4]` = `{p0, p1, p2, NULL}` | store values |
| `0x0EC` | `u_long n[4]` = `{0x40, 0x10, 2, 0}` | store values; `n == 1 << bits` |
| `0x100` | `u_long bits[4]` = `{6, 4, 1, 0}` | store values |
| `0x110`/`0x114` | big OT length `0x800`, bits `0xB` | `0x800 == 1 << 0xB` |
| `0x118`/`0x11C`/`0x120`/`0x124` | prim cursor / prim length `0x17700` / OT base / prim base | all four also written by the matched sibling `func_8001E160` |
| `0x128`/`0x12C` | work-area length `0x5EDC` / base | `func_800120C8`: `GsSetWorkBase(...->field_12C)` |
| `0x130` | VRAM staging base | `func_800128DC` memcpy target |

`ot[k].tag == org + ((1 << length) - 1)` in 4-byte `GsOT_TAG` units, verified
for all three live entries: `63*4 == 0xFC`, `15*4 == 0x3C`, `1*4 == 4`.
`ot[3]` is fully zeroed.

Every pool is carved out of the single `0x3EE50`-byte block at `0x801BE1B0`
that the leading `memset` clears:

```
+0x00000  p0  OT tags, 0x40 entries per buffer   cursor stride 0x100
+0x00200  p1  OT tags, 0x10 entries per buffer   cursor stride 0x040
+0x00280  p2  OT tags, 2 entries per buffer      cursor stride 0x008
+0x00290  big OT, 0x800 entries per buffer       cursor stride 0x2000
+0x04290  primitive buffers, 0x17700 each
+0x33090  work areas, 0x5EDC each
```

`0x33090 + 2*0x5EDC == 0x3EE48`, i.e. the work areas sit at the very end of the
memset region — the carve is exact, which is what makes the layout above a
reading rather than a guess.

### Store order is source order, and it reads as ordinary C

Each `GsOT` element emits at `+0x00, +0x0C, +0x08, +0x04, +0x10`. That is
`length`, then a **chained assignment** `ot->offset = ot->point = 0` (GCC
expands the inner store first, so `point` precedes `offset`), then `org`, then
`tag`. `ot[3]` adds `ot->tag = ot->org = 0`. The `0xD8`/`0xEC`/`0x100` block
emits column-wise: `org[k]`, `n[k]`, `bits[k]` for `k = 0..3`, then the big-OT
pair. No permutation search is needed for either block.

## 2. Loop 2 was a duplicate of an already-matched sibling

`func_8001E160` is matched and its body is instruction-for-instruction the
second loop of `func_80012598` — same TU, same global, same stride, same
`ClearOTagR` call and `0x176FF` byte-clear.

The parked attempt had rewritten it with decomposed address temporaries:

```c
addr1_shift = j << 13;
addr1_const = addr1_shift + 0x290;
addr1 = addr1_const + temp_s3;      /* -> addu a3,a3,s3   (wrong order) */
```

E160 writes the whole address as one expression, which reassociates the
constant into the variable part and puts the base first:

```c
base2[0x48] = temp_s3 + 0x290 + (j << 13);       /* -> addu a3,s3,a3 */
base2[0x49] = temp_s3 + 0x4290 + (j * 0x17700);  /* -> addu v0,s3,v0 */
```

That two-line change made the whole second half byte-exact
(61 → 59 differing words; highest differing address moved to `0x800127D8`,
the loop-1 branch delay slot). It had been sitting there across the entire
escalation ladder.

**Rule this generalises to:** before authoring a variant, grep the target's
globals across matched `src/`. A matched function that shares the struct is
both the idiom prior and, sometimes, a literal duplicate of part of the body.

## 3. The loop-1 mechanism, measured

### 3.1 The 16 copies are emitted by reload, not by CSE

**Corrected 2026-08-11.** An earlier draft of this note attributed the copies
to CSE. Counting whole-pattern reg-to-reg sets per pass dump settles it:

```
cse 3   gcse 6   loop 4   cse2 5   flow 4   combine 4   regmove 4
sched 4   lreg 4   greg 18   flow2 18   sched2 18
```

`lreg 4 -> greg 18`: **global allocation and reload add 14 of them.** The copies
are reload materialising base-equal pseudos that lost a hard register, not CSE
artifacts. Two consequences that matter:

- A pseudo qualifies for that treatment only if local-alloc's
  `update_equiv_regs` can mark it equivalent to a live register, which requires
  it to be **set exactly once**. A three-step respell (§3.4) is set three times,
  so it never qualifies: it is allocated a register instead, and then every
  extra copy costs one register. That is the linear trade measured in §4.
- The store-to-web grouping in §3.2 (4, 6, 2, 8 stores per register) is a
  reload-inheritance artifact, not a source structure. Trying to reproduce that
  partition from source variables is chasing a downstream output — several
  sessions of this note's history were spent doing exactly that.

The source respelling still controls the *number* of base-equal pseudos, so the
A/B table below stands as a measurement; what it does not do is control which
stores share a register.

Measured A/B, same 40 stores both ways:

| Source shape | copies | result |
|---|---|---|
| one pointer variable, `p[idx]` throughout | 1 | 15 copies missing, all 6 reload `lw` gone (CSE forward-propagates) |
| typed `DB *`, `db[i].field` (true ARRAY_REF) | 1 | 15 copies missing, 8 `lw` missing — **refuted** |
| repeated cast respell `((s32*)((u8*)&SYM + i*0x134))[idx]` | 16 | 12 land at their exact target addresses |

So the number of copies is set by how many times the source respells the base,
and it is not a free parameter to be searched. Hand-placing them is the trap
the previous sessions fell into.

### 3.2 The target's exact web partition

Read off the target with a def/use census over `0x80012644..0x800127D8`
(script preserved in the session scratchpad; the same numbers come out of
`explainDiff`'s web-parity section). 21 webs, chain `base → vA → {vB, vC} → 13
single-use copies`:

| Web | Def | Stores (offsets) |
|---|---|---|
| `a1#2`/`a3#2`/`t6#2` | `addu rX,t7,rX` | `org[0]`/`org[1]`/`org[2]`, one each, offset 0 |
| `a0#1` = base | `addu a0,s0,t7` | `0xEC, 0xF0, 0xF4, 0x114` |
| `v1#3` = vA | `move v1,a0` | `0x100, 0x104, 0x108, 0xF8, 0x110, 0x120` |
| `v0#6` = vB | `move v0,v1` | `0xE4, 0x10C` |
| `v0#9` = vC | `move v0,v1` | `0x84, 0x8C, 0x88, 0x98, 0xA0, 0x9C, 0xAC, 0xB4` |
| 13 singles | `move rX,v0` | `0x90`, `0x94`, `0xA4`, `{0xA8,0xB0}`, `0xB8`, `0xBC`, `0xC0`, `0xC4`, `0xC8`, `0xCC`, `0xD0`, `0x128`, `0x12C` |
| `s1#0` | running byte pointer | `0x16`–`0x1B`, `0x130` |

`$s0` (`&D_8005E5E8`) has exactly **5 uses** and is dead after index 51:
`move s1,s0` plus the four in-loop address forms. Anything that keeps `s0`
alive through the body is the wrong shape.

### 3.3 Why the reload `lw`s exist

`sw s2,0(a1)` … many stores through `a0/v1/v0` … `lw a0,0(a1)`. Because the
intervening stores go through pseudos CSE cannot relate to `a1`, the memory
equivalence is invalidated and `org[k]` is reloaded — twice per pointer, once
for `ot[k].org` and once for `ot[k].tag`. With a single base pointer the store
and the load are the same register at different constant offsets, CSE proves
independence, and all six loads disappear. The loads are therefore a
consequence of the multi-pseudo web, not an independent feature to reproduce.

### 3.4 The three-step respell is a hoist blocker, not transcription

```c
v = (s32 *)(s0 + OFF);
v = (s32 *)((u8 *)v + t7);
v = (s32 *)((u8 *)v - OFF);      /* net value == s0 + t7 */
```

The destination is written more than once, which disqualifies the insn from
`loop.c`'s `move_movables` (it requires `n_times_set == 1`) and disqualifies
the value from strength reduction. Written any other way, `s0 + OFF` is a loop
invariant, gets hoisted to the preheader, and GCC then rebases every store in
the loop onto `s0 + OFF` — the store offsets come out as `20(a0)` instead of
`236(a0)`. This is why the previous session's source looks the way it does; it
is load-bearing and should not be "cleaned up" without re-measuring.

It compiles to **one** instruction (a `move`): `cse2`'s `simplify_plus_minus`
reassociates `((s0+OFF)+t7)-OFF` to `s0+t7`, finds that value already live, and
rewrites the set's source to that register; the two intermediates die and flow
deletes them. So the form is not expensive in instructions.

It *is* expensive in registers, for the reason in §3.1: three sets means no
`reg_equiv`, so the pseudo must be allocated rather than rematerialised. That is
the pressure that makes the last web unreachable (§4).

A single-set respell does qualify for rematerialisation — but every
single-statement form that equals `base` is textually identical
(`v = (s32 *)((u8 *)s0 + t7)`), so CSE collapses them all into one pseudo
(measured: 185 instructions, 14 copies lost). Only five structurally distinct
single-set anchors exist (`s0+t7`, `ptr_D8-0xD8`, `ptr_DC-0xDC`, `ptr_E0-0xE0`,
and the byte pointer `s1`), which is not enough for 16. **Finding a
single-set, per-view-distinct spelling is the open problem.**

### 3.5 The cursors cannot be strength-reduced from an index

`build/compilerTrace/func_80012598/func_80012598.i.loop`, on a source that
wrote the pool cursors as `0x801BE1B0 + i * 0x100` etc.:

```
Insn 140: giv reg 137 ... benefit 3 lifetime 2 ... mult 256 add 0
Insn 201: giv reg 165 ... benefit 3 lifetime 2 ... mult 64  add 0
Insn 262: giv reg 193 ... benefit 3 lifetime 2 ... mult 8   add 0
Insn 462: giv reg 289 ... benefit 3 lifetime 2 ... mult 8192 add 0
...
giv of insn 462 not worth while, -124 vs 180.
giv of insn 262 not worth while, -124 vs 180.
giv of insn 201 not worth while, -124 vs 180.
giv of insn 140 not worth while, -124 vs 180.
```

A power-of-two multiplier compiles to one `sll`, so the giv's benefit is 3 and
`loop.c` rejects reduction outright; `i` then stays live, which also blocks the
`check_dbra_loop` reversal the target's `fp` countdown depends on. By contrast
the `i * 0x134` givs get `benefit 49/53` (a 7-instruction shift/add chain) and
long lifetimes, and reduce cleanly.

The target has all five cursors as running registers
(`addiu s2,s2,0x100`, `addiu t8,t8,0x40`, `addiu t9,t9,8`,
`addiu s3,s3,0x2000`, `addu s4,s4,s6`) plus a spilled `i*0x5EDC` at
`0x10(sp)`. Since the index form provably cannot produce them, they must be
written as **explicit source cursors**. That is not a violation of the style
guide's "walking pointers are strength-reduction products" prior: these are
pool-carving cursors with five different strides, which is the idiom the guide
itself lists under flat-initialised lookup tables.

### 3.6 Register pressure is at the ceiling

`triage`: frame `0x40` = args `0x10` + vars `0x8` + saves `0x28` (10 registers).
The target holds 13 loop-carried values (`s0`–`s7`, `fp`, `t7`, `t8`, `t9`,
plus the spilled `i*0x5EDC`) and up to ~13 base-equal body pseudos at the peak,
which is the entire allocatable file with exactly one spill. Any extra
simultaneously-live value spills, and a spill costs 5 instructions
(preheader `sw`, in-loop `lw`/`sw`, plus a load-delay `nop`).

## 4. The exact residual

### 4.1 Where it stands

The preserved attempt has the target's **opcode multiset exact except four
instructions of spill traffic**: all 16 base-equal copies are present and
`diffFunc` reports the whole count delta as `compiled has extra 2x lw, 2x sw`.
Semantics, inventory and web *population* are therefore all correct; the only
thing wrong is that two values that hold registers in the target do not here.

Quantified with a peak-overlap measurement (per-web live spans over the loop-1
body, counting only base-equal webs):

| Variant | copies | peak overlap | spills | differing words |
|---|---|---|---|---|
| target | 16 | **12** | 1 (`i*0x5EDC` at `0x10(sp)`) | — |
| preserved attempt | 16 | 14 | 3 | 95 (213 insns) |
| one view moved to a cheap anchor | 15 | 13 | 2 | 99 (210 insns) |
| two views moved | 14 | **12** | 1 | 67 (207 insns) |

The trade is exactly one register per copy, for the `update_equiv_regs` reason
in §3.1. Closing it needs a source form that adds a base-equal pseudo **without
consuming a register**, i.e. a single-set respell — see the open problem at the
end of §3.4.

### 4.2 Two findings from this round that change the setup

**The loop counter must not be a source-level literal.** The target has **two**
`addiu reg,$zero,0x1` (`$s5` at `0x800125F0`, `$fp` at `0x80012634`). Writing
loop 1 as `s8 = 1; do { ... s8 -= 1; } while (s8 >= 0);` makes the counter's
initial value the same literal `1` as the `s5` constant used by the DRAWENV byte
stores and `ot[2].length`; `cse2` merges them into one web, and reload then has
to materialise a second register for the counter — which is both the missing
`li` and one of the spills. `check_dbra_loop` reversal of a count-up `for` does
not help on its own, because `cse2` runs *after* `loop` and merges the reversal's
constant too.

What did work: **one counter variable shared between loop 1 and loop 2** (the
style guide's §12 idiom). Loop 1 uses `j` as its countdown and loop 2 reuses `j`
as its index. That alone moved peak overlap from 13 to the target's 12 and got
the count delta down to a single missing `move`.

**The tidier 55-word variant** (208 cc1 instructions, 14 copies + one `addiu`,
peak overlap 13) is the preserved attempt with two changes: drop the shared
counter (use a private `s8` countdown), and form the `0xA8`/`0xB0` view as the
one-instruction `view_A8 = (s32 *)((u8 *)ptr_DC - 0xDC)` instead of a three-step
respell. Reconstructable in two edits if a score-based comparison is wanted.

### 4.3 Refuted, with the measurement

- **Typed struct array** (`DB *db`, `db[i].field`): collapses to one base
  pseudo; 15 copies and 8 loads missing. The `ARRAY_REF` note in
  `include/globals_override.h` is about address *form*, not web population.
- **Two-step respell from `base`** (`v = base + OFF; v = v - OFF`): combine
  cancels the constants; all 14 copies vanish.
- **One-instruction respell from the offset pointers** applied to several views
  at once (`ptr_D8 - 0xD8`, `ptr_DC - 0xDC`, `ptr_E0 - 0xE0`): the views merge
  with each other and with `base`; 4 copies lost.
- **Birth-order of the counter / `i*0x5EDC` init** (three orderings): byte-identical
  output. Consistent with the style guide's "init-statement order is a codegen
  no-op on GCC 2.95".
- **Late birth of the cluster views** (each immediately before its use): loses
  3 copies and reintroduces a spill.
- **Sweeping the three-step respell's normalisation constant** (9 values:
  `0x94, 0x98, 0x8C, 0x100, 0x110, 0x120, 0x84, 0x134, 0x4`): all nine compile
  **byte-identically**. `cse2`'s `simplify_plus_minus` erases the constant, so
  these are one experiment, not nine.
- **Identical single-statement respells** (`v = (s32 *)((u8 *)s0 + t7)` repeated
  per view): CSE collapses them to one pseudo — 185 instructions, 14 copies lost.
- **A single base pointer with no respells at all**: 185 instructions, peak
  overlap 5, and four stores plus three loads eliminated. Too little pressure for
  the pointer to lose its register, so no reload copies at all.
- **Byte-pointer-anchored views** (`v = (s32 *)s1`, single-set and therefore
  remat-eligible): each conversion frees a register but loses a copy — the same
  linear trade from the other direction.
- **Merging stores onto the shared `vC` web** to match the target's 8-store
  group: each merge *reduces* the copy count, because CSE folds more once the
  base register is shared. The 8-store group cannot be built by merging up from
  a finer partition.

### 4.5 The user-granted asm/pinning exception: what it bought, and why it is not promoted

On 2026-08-11 the user explicitly granted an exception to the clean-source
policy ("even if you have to introduce some hybrid asm"), which `AGENTS.md`
defers to. It was used, measured, and **not promoted**, because the skill's rule
is explicit: an exemption recorded for a function that still does not match
asserts to every later agent that the exempted construct is the right answer,
and that assertion would be false here. The measurements are kept because they
localise the residual precisely.

Narrowest useful intervention: pin the twelve loop-carried values to the
registers the target gives them —

```c
register u8 *s0 asm("$16");  /* &D_8005E5E8 */   register s32 t7 asm("$15");
register u8 *s1 asm("$17");  /* byte pointer */  register s32 t8 asm("$24");
register s32 s2 asm("$18");  /* cursors ... */   register s32 t9 asm("$25");
register s32 s3 asm("$19");                      register s32 s8 asm("$30");
register s32 s4 asm("$20");                      /* + temp_a2 -> $6 ($a2) */
register s32 s5 asm("$21");  /* const 1 */       /* + ptr_E0  -> $14 ($t6) */
register s32 s6 asm("$22");  /* 0x17700 */
register s32 s7 asm("$23");  /* 0x801BE1B0 */
```

| Variant | instrs | differing words |
|---|---|---|
| clean C, same body | 215 | 103 |
| + 12 loop-carried pins | **209 (exact)** | 74 |
| + `temp_a2` -> `$a2` | 209 | 69 |
| + `ptr_E0` -> `$t6` | 209 | **65** |
| + six cluster views pinned to `$t0`-`$t5`, copies forced with a one-instruction `addu %0,%1,$zero` asm | 211 | 59 |
| + those six as plain C assignments (compiler deletes the copies) | 196 | 44 |

So the exception buys an exact instruction count and takes the residual from 103
to 65 differing words, but it does **not** close it. Pinning cannot express the
target's caller-saved structure, because `$v0`, `$v1`, `$a0`, `$a1` and `$a3`
each serve two or three sequential roles in loop 1 (`$v0` alternates between
holding the base and being scratch for `li`), and a pinned local occupies its
register for its whole live range.

### 4.6 Two mechanism findings that redirect the next attempt

**The copies are reload rematerialisations with one-instruction live ranges.**
Refining §3.1: reload inserts each copy immediately before the use it serves, so
at allocation time those 16 pseudos cost nothing; `sched2` (which runs after
reload) then hoists them, which is why the target shows six of them bunched at
`0x80012714`-`0x80012728` and used forty instructions later. This is the
asymmetry that has defeated every source shape tried: the target's copies are
free, and every copy this reconstruction creates holds a register.

**A single transparent base pointer is semantically wrong, not merely
under-pressured.** With one clean `p` used for all ~39 stores, GCC deletes four
of them: loop 2 rewrites `0x110`, `0x114` and `0x120`, and with a transparent
pointer the compiler can prove loop 1's stores to those offsets dead
(`count delta: ... 4x sw the compiled side lacks`, 184-185 instructions, both
with and without the pins). The original's addressing must therefore be opaque
enough to defeat that proof, which is independent evidence for the
respell/offset-pointer family and against any form that gives the optimiser a
clean single pointer.

Together these say the wanted source has **many base-equal pseudos that all fail
global allocation**. That remains the open problem, and it is the whole content
of the policy debt: a single-set, per-view-distinct C spelling of a base-equal
copy. Single-set forms qualify for rematerialisation but every
single-statement spelling that equals `base` is textually identical
(`v = (s32 *)((u8 *)s0 + t7)`), so CSE collapses them into one pseudo (measured:
185 instructions, 14 copies lost). Only five structurally distinct single-set
anchors exist -- `s0+t7`, `ptr_D8-0xD8`, `ptr_DC-0xDC`, `ptr_E0-0xE0`, and the
byte pointer `s1` -- and sixteen are needed.

## 5. Process lessons

1. **Diff the matched siblings in the TU first.** Free, and here it was half
   the function.
2. **Decode the data model before writing C.** SDK struct sizes are
   fingerprints (`0x14` = GsOT/DISPENV, `0x5C` = DRAWENV); `1 << n` value pairs
   mean count/shift. Once typed, the store order reads as ordinary statements
   and the search space collapses.
3. **Count `addu rX,rY,zero` in the target.** It measures how many times the
   source respells the base address. It is a source-shape reading, not a
   placement puzzle.
4. **Gate on instruction-count parity, and get the count from a tool that
   knows about assembler delay-slot fills.** The prior session tracked
   word-match (144 → 106 → 61) inside a 207-instruction family that could
   never reach the target; `diffFunc`'s raw 209 hid the fact that 208 is the
   cc1 count.
5. **A model escalation ladder cannot fix a representation defect.** Every tier
   inherited the previous tier's source shape and searched inside it.

## 6. How the match was actually reached (the policy exception)

Granted by the user on 2026-08-11; `AGENTS.md` defers the clean-source policy to
explicit user instruction. Recorded here in full because the skill's rule is
that an allowlist entry asserts the exempted construct is the answer for the
function, and that assertion needs its evidence attached.

The winning source states loop 1 in the target's own register roles, with the
stores, cursors, constants and both loops as ordinary C. Loop 2 is untouched
plain C. What the exception buys, in order of how much:

1. **18 `register ... asm("$n")` pins** (`s0`, `s1`, `s2`-`s7`, `t7`-`t9`, and
   `rV0`/`rV1`/`rA0`/`rA1`/`rA3`/`rT6`/`temp_a2`). The target's allocation is
   literally "one variable per register, reused sequentially" -- `$v0` alternates
   between holding the base and being `li` scratch, `$a0` serves the base then
   `0x94` then `0xA8`/`0xB0` -- which pinning can express and priority-based
   allocation would not reproduce. A greedy minimisation pass removed six pins
   (`rT0`-`rT5`); the remaining 18 are each load-bearing.
2. **Twelve one-instruction `addu %0,%1,$zero` copies** (`COPY`). A plain C
   assignment between two same-valued pointers is deleted (CSE substitutes the
   source register at every use); four of the sixteen copies do survive as plain
   C and are written that way.
3. **Two zero-instruction ordering barriers**
   (`__asm__("" : "=r"(x) : "0"(x))`), the form the style guide already governs.
   They fix two pure sched2 rotations that no source order moved: `li s5,1`
   against `lui s4`, and `addu a1,t7,a1` against `addu a0,s0,t7`.
4. **One `addiu %0,%0,-1` for the loop counter** and **one `lui`/`addiu` pair
   for the symbol address**. The latter is needed because a pinned `s0` makes GCC
   use `$s0` for both halves, where the target uses `$v0` as the `%hi` temp.
5. **One `__asm__("" : : "m"(sp10))`** to keep `sp10` in the frame at
   `0x10(sp)`. Note this asm has no outputs and is therefore *implicitly
   volatile*: it is a store barrier, and its placement matters. Put before the
   two `%gp_rel` stores it holds them at the end of the preheader, which is where
   the target has them; put after, it drags them 19 instructions early and costs
   25 linked bytes.

### Traps worth knowing

- **`diffFunc --src` gave a false MATCH-looking result.** It reported
  `VERDICT: MISMATCH -- 0 word(s) differ` with `Match: 206/209`, which means
  every instruction is present and correct but three are *displaced*; the linked
  binary differed in 25 words. This is `notes/.../masked_diff_blindness`
  territory: `--bytes` or `make check` is the verdict once displacement is the
  residual, because a rotated block shifts many addresses while differing in no
  compared pair.
- **A volatile asm is a scheduling barrier for stores.** Using one to pin
  `li s5,1` re-hoisted the two `%gp_rel` stores and made things worse; the
  non-volatile `"=r"/"0"` barrier form is the right tool for pure ordering.
- **Sweeping a respell's normalisation constant is one experiment, not nine.**
  Nine offsets compiled byte-identically -- `cse2`'s `simplify_plus_minus`
  erases the constant.
