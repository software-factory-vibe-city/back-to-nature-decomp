# func_80020E58 retro — allocation residual [0,0,6,30] to byte-exact (2026-08-17)

Closed the VAB transfer dispatcher at 276/276 (`psx_finalize_function` passed;
full payload byte-identical). Inherited at [0,0,6,30] (blocks 2/3/6/8, greg
owner) after **four prior sessions** whose running conclusion was that case 0xA
(the `move a2,a3` copy) was *instrumentally proven blocked* and case 0x28 was
an untestable quantity-order cascade.

Every one of those "proofs" was correct **within the source's own
declarations** — and that was the trap. The fix was three declaration/idiom
truths that had been sitting in the repo the whole time.

## The three idioms (decreasing order of impact)

1. **`SsVabOpenHead` takes TWO arguments.** The vendored `libsnd.h` says
   `short SsVabOpenHead(unsigned char*, short)`. I had invented a 3-arg
   prototype (`+ D_8005E544`) and even wrote a comment rationalizing that the
   header "does not describe this call". The phantom third arg made GCC emit a
   copy `(set a2, P)` for a nonexistent argument — the *exact* instruction that
   the scheduler places inside the value web's live window, excluding `$a2`,
   which was the entire "proven blocked" case-0xA residual and the `+1`
   instruction count. Fixing the arity cleared the block in one shot.
2. **Base-pointer idiom for the second-half arrays.** `s32 *c028 =
   &D_8006C028; s32 *c068 = &D_8006C068; s32 *ba8 = &D_8006BFA8;` then index
   them — copied from the matched sibling `func_80020818`, which uses exactly
   `s32 *var_s3 = &D_8006C068` for these same arrays. Materializing the base
   quantities (that the inliner's CSE never created as allocatos) gave case
   0x28 the target's register roles ($v0/$a3/$a2 for the C028/C068/BFA8 bases)
   and cleared all 14 allocation differences.
3. **`func_80021604` is `void`.** Its definition TU declares `void`. My source
   comment claimed "its return value is stored into D_8006BFA8" — a misread of
   the delay-slot `sw v0,0(v1)`, which stores `head` (still in `$v0`), not a
   return value. The phantom non-void return kept a `$v0`-return web alive after
   the call, so `li 60; sw ...,D_8005E538` loaded the constant into `$v1`
   instead of reusing dead `$v0`. Those were the last 2 differing bytes of the
   entire binary.

Also in this session, before the idioms: the **partial 0x1E+0x32 `value`
merge** — one function-scoped `s32 value` assigned in both case bodies — moved
[0,0,6,30] → [0,0,2,16] by clearing blocks 6/8. Prior sessions tried the
*full* function-scope merge (became a global allocno, forced `$s2`, frame grew)
and the inline form (reload after the call); nobody tried the partial merge
that reproduces the target's `$s0`-in-both-arms web.

## Why the "impossible" readings were so expensive

Count, opcode multiset, inventory, and (masked) web shapes were all plausible
under the wrong declarations; the diff read as a pure register-allocation
rotation, and every allocator/scheduler tool downstream analysed that frame
without complaint:

- The instrumented local-alloc oracle honestly rejected `233:$a2` ("excluded
  over the lifetime") — but the lifetime exclusion came from the phantom
  arg-copy the wrong prototype manufactured.
- The scheduler class-tie analysis (store wins the pre-call slot on the
  REG_DEP_ANTI tie, so the copy stays inside the value's window) is real and
  deterministic — but it can only ever explain the candidate's RTL; it cannot
  guess the original's RTL, which had no copy at all.
- A bounded "exhaustive spelling" burst (11 variants across statement-order,
  two-set locals, split webs, named lengths) returned all identical or worse —
  correctly signalling that the answer was *a different program shape*
  (a declaration / an arity / an idiom), not a spelling.

## The reusable lesson

**"Proven blocked" is only valid up to the declarations.** When a residual
survives exhaustive spelling, the first move is to re-audit every callee
prototype and type against ground truth — the vendored SDK headers and the
already-matched sibling functions in the same file group — *before* (or
alongside) compiler-source forensics. The skill's own up-front checklist says
this ("a wrong prototype adds call-setup moves and corrupts every web and
allocation analysis downstream") and it was skipped precisely because the
session had gone too deep into forensics to revisit it. An exhaustive-spelling
batch that lands all `identical` is evidence the residual is declaration- or
idiom-shaped, not an argument to stop.
