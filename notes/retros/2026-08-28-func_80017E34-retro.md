# Retro: func_80017E34 — 27 instructions, a 4-word register swap, and the tie that never existed

Final state: byte-verified match (27/27, `VERDICT: MATCH`, full finalizer
gates pass), clean C89, baseline flags, no policy exceptions. The entire
fix relative to the stuck state: write the pre-check re-read and the loop
store value as **one shared user variable** instead of two fused
expression temporaries:

```c
*arg0 = *arg1;          /* store value: fresh load -> $v0 (must NOT be c) */
c = *arg1;              /* re-read: shared var -> $v1 here AND in the loop */
if (c != 0xFFFF) {
    term = 0xFFFF;
    arg1++;
    do {
        c = *arg1;
        *++arg0 = c;
    } while (*arg1++ != term);
}
```

The function is u16 strcat from an unreachable library TU (see
`notes/file-groupings.md`, "u16 string library"). It consumed a
multi-session investigation that produced an instrumented-compiler oracle
proof, a scheduler-state SAT search (UNSAT on block 5), an exhausted
residual source-space search, and a long dossier of rejected variants —
all circling a local-allocation priority tie.

## 1. The wrong model, and why it was sticky

The inherited model: the loop's store-load and compare-load are two local
quantities with exactly equal priority (measured: refs 4, window 4,
QTY_CMP_PRI 20000 == 20000), tie broken by birth order, load born first,
so the load takes `$v0` and the original must have perturbed the tie
somehow.

Every clause was *true of the candidate*. The oracle even proved that
forcing the opposite assignment reproduces the target byte-for-byte. That
combination — internally consistent, evidence-backed, sufficient-looking —
is exactly what made it expensive: it implied a search space (perturb
refs/lifetimes/birth order inside the do-while family) in which every
experiment compiled to the identical quantities. Each tool then correctly
answered the question the model asked: scheduler-state search proved no
serialized state breaks the tie (UNSAT), the residual search proved no
reachable shape in the family helps. Both were read as "search harder"
instead of "wrong room."

The false premise was hidden in step one: *that the original compilation
had two local temporaries at all*. In the original, the store value was a
multi-block user variable — a global allocno — so the tie never existed
and there was nothing to break.

## 2. What cracked it

Reading the **target's** register assignments as a web census instead of
diffing against the candidate: `$v1` serves as the pre-check re-read AND
the loop store-load (in this function and in the byte-identical loop of
sibling func_80017EA0). One register, one role, two blocks, systematic
across the TU — that is one shared variable, not two temporaries.

From there the mechanism is forced (full detail in
`notes/research/func_80017E34-shared-web-global-allocno.md`): a variable
set in two blocks fails local-alloc's locality test
(`REG_BASIC_BLOCK >= 0 && REG_N_DEATHS == 1`), becomes a global allocno,
conflicts with the block-4 0xFFFF constant's `$v0` (which is live across
its compare), and takes `$v1` in both blocks. The loop compare re-read
stays the only block-5 local and takes `$v0`. 27/27 on the first compile
of that shape.

## 3. Effort inventory (what was tried and rejected, and why)

- Post-increment / pre-increment / named-temp / commuted-compare variants
  of the do-while: all compile to the identical quantities → same tie.
  (Family is one point in the search space.)
- `while` top-check forms: normalized to byte-identical RTL by GCC 2.95 —
  not a distinct experiment.
- `for(;;)` + if/break (the strcmp sibling's style): different loop
  structure entirely (0/17 on the testbed); the target's layout requires
  the bottom-tested do-while.
- Multi-set store value with the compare fused to it (v_cvar family):
  collapsed the two loads to one web — but the target has two distinct
  `lhu` targets, so a single web for BOTH loads is structurally wrong;
  and it perturbed the scan-loop pre-check scheduling. Rejected.
- Inline `0xFFFF` instead of the `term` variable: loses the delay-slot
  `ori $a2` (CSE merges the constants) — the two 0xFFFF materializations
  in the target require two webs.
- Scheduler-state SAT on block 5: UNSAT — correct certificate that no
  serialized scheduler state breaks the tie; should have been read as
  family-level evidence, not per-shape evidence.

## 4. Lessons

1. **Census the target's registers before diffing against your own
   output.** Same hard register, same role, two blocks → suspect one
   shared user variable (a global allocno), especially when the pattern
   repeats in sibling functions of the same TU.
2. **A verified mechanism of your candidate is not a measurement of the
   original.** "Forcing the assignment reproduces the target" proves
   sufficiency, not history. The original may never have passed through
   the pass you are modeling.
3. **Structural ties are a stop sign, not a puzzle.** When refs,
   lifetimes, and birth order are all pinned by the dependency graph, the
   tie cannot break from inside the expression family. Change the web
   population (shared variable, fused temporary), not the phrasing.
4. **Check family exhaustion at the `.lreg` dump, not the score.** Two
   variants with identical quantity structure are the same experiment;
   the match score cannot tell them apart.
5. UNSAT from a scheduler-state search excludes the *domain*, and the
   domain was derived from the model. When the model is wrong, UNSAT is
   a perfectly correct proof about an irrelevant space.
