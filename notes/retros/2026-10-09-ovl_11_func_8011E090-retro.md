## 2. The address block: materialisation order

The target builds the table address in this order:

1. the far base `D_8007AFF0`;
2. the scaled cell offset `(row * 45 + col) * 4`;
3. `base + 0x20000`, which is shared with the mode halfword at +0x5476;
4. the table pointer;
5. a base-first `addu table, offset`.

Writing the offset as one expression after `p = base + 0x20000` puts the
index chain after the high part, and the `addu` operands in the other order.

| spelling (`build/e090_claude/`) | block 7 |
|---|---|
| one expression after `p` (the parked form, `v2/a1_*`) | `0/2/10` |
| unscaled index statement before `p` (`v2/a3_*`) | `0/1/0` |
| scaled offset statement before `p` (`v3/b*`) | clear, but the `addu` operands are swapped |
| scaled offset, then `p`, then `tbl = p + 0x3608`, then `*(tbl + idx)` (`v5/d5`, committed) | clear and word-exact |

**Transfer:** when the target computes an address's index chain before its
base split, write the scaled offset and the table pointer as their own
statements, in the target's order.

## 3. The return: jump.c's assignment hoist

The target's tail:

```asm
bne   v0,a1,exit      # mode != 6
 move v0,zero
lw    v0,0(v1)
andi  v0,v0,0x8
bnez  v0,exit         # entry & 8
 move v0,zero
li    v0,1
exit:
```

Both failing tests branch to a `return 0` block. Reorg copies that block's
`move v0,zero` into each delay slot and the block disappears. That only
happens if, at reorg time, the flag test still branches to `return 0` and
falls through into `return 1`.

The first jump pass rewrites that shape away (`jump.c:596`):

    if (c) { x = a; goto l; } x = b;   ->   x = a; if (!c) goto l; x = b;

It requires the conditional jump's target label to come immediately after the
`goto` of the `x = a` arm. Every tidy spelling of the tail satisfies that:

| tail spelling | what jump.c does | result |
|---|---|---|
| `if (m != 6 \|\| f) return 0; return 1;` (parked) | `:596` fires | `beqz` with `li v0,1` in the slot; fallthrough `move v0,zero` |
| nested `if (m == 6) { if (!f) return 1; } return 0;` | `:596` fires | same inverted form |
| `if (m == 6 && !f) return 1; return 0;` | `:596` fires | same inverted form |
| `if (m != 6) return 0; if (f) return 0; return 1;` | `:596`, then store-flag (`:870`) | `sltiu` |
| result variable, single `return` | store-flag | `sltiu` into a temporary plus a move |
| `if (m == 6) { if (!f) return 1; } else { return 0; } return 0;` (committed) | `:596` blocked | target |

The `else { return 0; }` arm places a second `return 0` block between the
`return 1` arm's `goto` and the label the flag test jumps to. The jump-pass
dump of the committed source (`build/e090_claude/final.i.jump`) shows:
- the mode test jumps to label 253, the else arm;
- the flag test jumps to label 262, the final `return 0`;
- the real insn before label 262 is the else arm's `goto`, so the rewrite's
  adjacency check fails.

The sibling `ovl_11_func_800D7EF8`, still a stub, is the same routine for the
45x25 grid. It is reached from the same call site with the same prototype,
and its target tail is the inverted form. The tail shape is therefore a fact
about each function's source, not about the toolchain.

**Transfer:** a conditional branch whose sense is inverted, with the return
constants swapped between delay slot and fallthrough, belongs to jump.c's
assignment hoist or store-flag fold. Diff the expand dump against the
jump-pass dump to see which fired. The source lever is the label layout after
the `goto`: an extra arm returning the same value blocks the hoist. Spellings
that tidy the logic all normalise to the same output.

## 4. The prologue and the signature

- **Write it naturally.** Once the two defects were fixed, natural C matched.
  - The signature `(VECTOR *pos, u16 *colOut, u16 *rowOut)` follows the
    caller `ovl_11_func_801103E8`'s 3-argument prototype; the parked attempt
    had a spurious fourth parameter.
  - Plain `pos->vx` / `pos->vz` reads work: GCC narrows them to `lhu` itself.
  - The u16 outputs give the target's `lhu` + `sll`/`sra` reloads.
- **One oddity is real.** The target copies all 16 bytes of `*pos` into its
  frame and never reads the copy, so the source keeps `copy = *pos;`. Reading
  the copy instead of `pos` (`build/e090_claude/v7/p2.c`) moves the residual
  to `[0, 0, 5, 4]`.
- **Filed, not changed.** `ovl_11_func_801103E8` declares the argument as
  `Recon800D0408A1View`, which is 12 bytes. The callee copies 16 bytes, and
  the caller's slot at sp+0x10 has room for 16. This disagreement is for the
  owner of that declaration.
