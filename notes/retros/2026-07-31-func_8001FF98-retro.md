# Retro: func_8001FF98 — period idioms, flag hypotheses, and tooling blind spots

Final state: byte-identical under the standard project flags with plain
period C. No override, no shield, no pinning. The function took three
sessions and substantial research spend; this retro captures why, what was
learned, and what was built so the next function of this class costs a
fraction.

## The arc (compressed)

1. **Blocked (7/83):** gcse loop-PRE hoists the bottom-of-loop counter
   increment past the nested inner loop; loop.c then finds no biv and
   nothing strength-reduces. Concluded "unreachable under -fgcse."
2. **Shield era (46/83):** derived the lcm.c equations; an artificial
   dead-store "isolation shield" defeats the hoist; plateaued on a
   register-allocation rank inversion no clean lever could move.
3. **Research:** three parallel investigations (period corporate style,
   decomp-community GCC 2.9x tricks, sound-driver source archaeology)
   produced the winning priors: naive count-up indexed loops, libsnd
   `[s_max][t_max]` tables with t_max == 1, shared counter variables, and
   the (wrong but productive) per-TU `-fno-gcse` hypothesis.
4. **Solved:** the first sweep of the naive space hit 83/83. A 13-byte
   residue exposed that all masked tools are blind to symbol transposition.
   Then flagProbe's matrix exposed that the flag override was unnecessary:
   **counter reuse across sequential loops is a natural PRE isolation
   shield** — the tail loop's `i + 1` isolates the outer loop's increment.
   The original never needed special flags; it needed 1999 style.

## Category 1: validated period idioms (now section 12 of the style guide)

- Count-up indexed `for` loops; countdowns in targets are check_dbra_loop
  reversals. (PSY-Q samples ~97% count-up; matched SH1/ESA corpora.)
- Naive indexed bodies — walking pointers, byte-offset accumulators, and
  countdown forms are compiler products; hand-writing them is both
  unidiomatic and (here) allocation-hostile.
- One counter variable reused across sequential loops — period habit AND
  natural PRE shield. Tell: last loop's counter register == earlier loop's.
- True 2D types even with a dimension of 1 (libsnd SEQ/SEP `[s][t]`).
- Literal bounds, int counters, `-1` empty sentinels, max+1 min-scan
  sentinels (Quake `0x7fffffff`, ours `0x01000000` = 24-bit payload + 1).
- Levers that DO work on 2.95: named constant locals (materialization
  order), statement order of same-shaped accesses (symbol-to-register
  assignment). No-ops: `register`, decl order, init order, `if (var) {}`,
  `do {} while (0)` fences.

## Category 2: tooling gaps found and closed

- **Masked-diff blindness (closed):** diffFunc and every positional harness
  mask relocations, so two same-shaped globals swapped between registers
  score 100%. FF98 shipped a "100%" that was 2 bytes wrong. diffFunc now
  auto-escalates masked 100% to a linked-binary byte comparison
  ("VERIFIED" or an itemized word diff with a transposition hint) and has
  parity with `make check` at function granularity. Tested both directions.
- **Flag heuristics (closed):** `tools/agent/flagProbe.ts` runs
  pre-decompilation: structural fingerprints decoded from target bytes
  (PRE-fatal nested-loop bottom increment → gcse question; lui/lw
  self-clobber → scheduling question), a flag-matrix score of current
  source, and nearby overrides (per-TU reasoning). Escalation bar in style
  guide section 11. Note its second use: a matrix showing baseline == delta
  KILLS a flag hypothesis cheaply (that is how the FF98 override died).

## Category 3: process lessons

- Run flagProbe (fingerprints) BEFORE source archaeology. The FF98
  fingerprint was visible in the target bytes from day one.
- Research before grinding: the three-corpus research cost a fraction of
  the two blind-sweep sessions and produced every element of the solution.
- A masked 100% is a candidate, not a result. Only bytes conclude.
- Policy note: the clean-source policy was ultimately vindicated (clean C
  under baseline flags existed), but resisting the flag *experiment* was
  wrong — the cheap test would have redirected the search a session
  earlier. The rule is now: experiments are cheap, adoptions need the bar.
