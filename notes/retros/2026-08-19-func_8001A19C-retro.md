# Retro: func_8001A19C — the last two schedule cells, and the array-index birth-site idiom

Final state: byte-exact (58/58), `psx_finalize_function` passed exact diff, full
build, scope, and clean-source gates. Clean C89, baseline flags, no pinning,
no assembly, no overrides. The nearest-neighbour grouping evidence was recorded
in `notes/file-groupings.md` (zero-gap adjacency with func_8001A11C, shared
u16-table GP cluster, same func_800191B4/func_8001945C drain idiom).

The function is a 3-iteration u16-table drain: for `i` in 0..2 call
`func_800191B4(D_8005E4A8, D_80049068[i], 1, count)`; on a hit advance
`D_8005E4A8` past the 0xFFFE tag, set the E4A0/E4AC/E4A2/E4B4/E4B8/E4A4
state cluster, store the parallel slot word to `D_8005E446`, and update
`D_8005E444` from `func_8001945C(D_8005E4A8, 0xFFFF, 0)`.

## Immediate replay checklist

For another function whose only residual is one or two *schedule* cells in a
constant/load store block, when statement permutations "do nothing":

1. **Prefer array indexing over explicit walking pointers for table reads in a
   drain loop.** The decisive difference here: `D_8005E446 = D_80049070[i]`
   compiled byte-exact, where `D_8005E446 = *tab;` (explicit pointer walked in
   the loop latch) did not. Loop strength reduction births the indexed load at
   the induction top-of-block, so its scheduler ready/block state differs from a
   pointer deref whose load is born at its (late) consumer statement. Try the
   indexed spelling before modelling webs for the pointer form.
2. **Keep a normalize-once check of the emitter's "loaded early" behaviour.
   The `*D_8005E4A8` read-through-the-global trick pins a store→load order and
   still CSEs back to the direct offset form, so the bytes match the "natural"
   direct read.** `if (*D_8005E4A8 == 0xFFFE)` emitted `sw v0,E4A8` then
   `lhu v1,2(a0)` — the target order — whereas `v[1]` alone let sched2 hoist
   the load. GCC folded the global read back to `2(a0)`, so there was no extra
   instruction. The sibling func_8001A11C uses the same read-through-global
   spelling.
3. **Birth loop setup before the induction-pointer materializations.** `i = 0;`
   first, then the two addresses, fixed the counter/pointer register roles
   (`i`→`$s1`, `D_80049068` ptr→`$s0`, `D_80049070` ptr→`$s2`).
4. **Incomplete-array externs get the split address form.** Absolute-addressed
   tables accessed outside the GP range must avoid `SYMBOL_REF_FLAG`, which the
   ENCODE_SECTION_INFO `-G8` size test sets for any declared 6-byte object.
   Declaring `extern u16 D_80049068[];` (unknown size) in `globals_override.h`
   produced the target `lui v0,%hi` / `addiu s2,v0,%lo` split form instead of
   the self-clobber `la` macro pair. (func_8001A574's retro chose a
   >-G8 sized array for the same effect; both set size INVALID/oversize.)

## The mechanism that was not a mechanism

The residual was a classic LUID/boost interaction in the store block. The
`lhu v1,0(s2)` (`*tab`) and the `li v0,1` (B4) land at positions 6 and 7 where
the target wants 2 and 5. Both are single-set (birth-boosted) loads/constants;
the boost makes the load win its ready-list contest and issue in the body of
the block, where the target's memory-unit blocking keeps it queued to the top
next to the a0-load. Confirmed from the real `.sched` dump: the *tab UID shows
`7f000001` and issues at T-9, while the a0-load is blocked six times and drifts
to position 1.

## What deliberately did NOT solve it (all measured)

- **Statement-order permutations of the stores** — provably inert (same
  compiled words) for every order of the A0/AC/A2/B4/B8/A4/E446 block; the
  scheduler's LUID-driven store picking is invariant to source store order.
- **Explicit walking pointer + shared 2-set web** for `v[1]`+`*tab`: de-boosted
  the load and fixed the block-6 schedule, but the cross-block web inherited
  `$a3` (born where the call argument dies), rotated `$v0/$v1` in block 4, and
  the local-alloc solve came back UNSAT within phantoms; the forced-local oracle
  reported `v0` excluded for the 0xFFFE quantity.
- **Same-block web reuse** (`tag = *tab; …; tag = 1;`): identical words — GCC
  splits same-block disjoint lifetimes into separate quantities, so the boost
  never drops.
- **Scheduler-state search**: could not derive a unique target-order assertion
  for block 6 (sched or sched2), because the target order is a memory-unit
  issue-window property, not a priority/LUID pair ranking.
- **Flag probe**: inconclusive, no target fingerprint; `-fno-schedule-insns*`
  destroys the instruction count; the escalation bar is not met.
