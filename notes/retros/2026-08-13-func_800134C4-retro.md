# Retro: func_800134C4 — the primitive was invisible because its code byte was composed

Final state: byte-verified 105/105, full build green, clean C89, baseline
flags, no policy exception. The load-bearing reconstruction is only this:

```c
setPolyF4(poly);
setRGB0(poly, color, color, color);
setXYWH(poly, 0, 0, 0x280, 0x1E0);
setSemiTrans(poly, 1);
setDrawMode(draw_mode, 1, 1, 0x140, 0);

addPrim(D_8005E3B4, poly);
addPrim(D_8005E3B4, draw_mode);
```

Same failure family as `2026-08-07-func_800140C8-retro.md`: the semantics were
never in doubt and the **operation boundary** was. There it was one block-move
instruction read as five scalar accesses. Here it is a 24-byte `POLY_F4`, a
12-byte `DR_MODE`, and two 24-bit ordering-table merges, read as hand-written
field stores and hand-rolled tag arithmetic.

The numbers below were re-measured against the current tools while the fixes
in `plans/sdk-idiom-first-decompilation.md` were built. Where a figure comes
from reconstructing the case rather than from the original session, it says so.

## 1. Why the detector was silent

`sdkIdioms` anchors on the `setlen`/`setcode` byte pair the SDK's primitive
initializers expand to. The target has both:

```
c0: sb v1,3(a0)   # v1 = 5
d8: sb v0,7(a0)   # v0 = 42 = 0x2A
```

`include/psyq/libgpu.h` has no primitive with code `0x2A`:

```c
#define setPolyF4(p)	setlen(p, 5),  setcode(p, 0x28)
```

The detector required `p.len === observedLen && p.code === observedCode`, so it
returned nothing at all, and the pre-fix run printed:

```
sdkIdioms func_800134C4: no PSY-Q primitive signature found.
```

`0x2A` is `0x28 | 0x02`, and bit 1 is documented in the same header:

```c
#define setSemiTrans(p, abe) \
	((abe)?setcode(p, getcode(p)|0x02):setcode(p, getcode(p)&~0x02))
```

So the composed byte is what the SDK *always* produces for
`setPolyF4(p); setSemiTrans(p, 1);` — ordinary composition, not an exotic
shape. Requiring the exact table code made the detector blind to the normal
case. The fix strips only bits the active header defines as attributes, and
refuses the match when any other bit differs.

The second gap was structural rather than arithmetic: `DR_MODE` is

```c
typedef struct {
	u_long	tag;
	u_long	code[2];
} DR_MODE;
```

and the layout parser returned `null` for any struct containing an array, so
the 12-byte command packet could not be modelled at all.

## 2. What the residual looked like without the boundary

Re-measured on a hand-expanded reconstruction with the same semantics
(`explainDiff` against the target):

```
target:      105 instructions
compiled:    106 instructions
Classification: instruction-selection
  - 79/106 instructions match exactly by index.
```

One instruction over, a broad register rotation, and a classifier pointing at
instruction selection. Every reading available downstream — allocation,
scheduling, web parity — describes a program the original build never
compiled, because the source asked for a different set of instructions.

## 3. What the target actually establishes

`psx_sdk_idioms func_800134C4` now reports two objects and two links, all of it
parsed from the configured header rather than restated in TypeScript:

```
POLY_F4 via setPolyF4 composed with setSemiTrans
  observed code 0x2A = base 0x28 | setSemiTrans bit 0x2
  writes r0/g0/b0                 -> setRGB0(p, r, g, b)
  four screen points, one rectangle -> setXYWH(p, 0x0, 0x0, 0x280, 0x1E0)

DR_MODE via setDrawMode
  word at +0x4 = 0xE1000740, word at +0x8 = 0x0
  dtd = 1 (exact), dfe = 1 (exact), tpage = 0x140 (compatible), tw = 0 (exact)

2 complete addPrim operations over 1 ordering-table pointer
```

Two recognition facts are worth carrying forward:

- **The command word inverts.** `_get_mode(dfe, dtd, tpage)` is a top-level
  `|` chain of a literal command constant, two `(flag ? BIT : 0)` attribute
  bits, and one `(arg & MASK)` passthrough. Inverting `0xE1000740` against that
  structure recovers `dfe=1, dtd=1, tpage=0x140` — which is what the matched
  source passes. The masked argument is labelled `compatible` rather than
  `exact`, because only the `0x9FF` bits of `tpage` reach the packet.
- **`setTexWindow` and `setDrawStp` are refuted, not merely outranked.** Both
  write the same two words at the same offsets with the same `len`, so length
  and geometry cannot separate them. OR never clears a bit, so the literal
  command constant of each expansion is a necessary condition on the observed
  word: `0xE1000740 & 0xE2000000 != 0xE2000000` kills `setTexWindow`, and
  `& 0xE6000000` kills `setDrawStp`.

The link is the whole dataflow, not the mask constant. `addPrim(ot, p)` is two
complete merges:

```
128: lw   v1,0(a0)     ; 154: lw   v1,0(a1)
130: and  v1,v1,a3     ; 15c: and  v1,v1,a3      a3 = 0xFF000000
134: and  v0,v0,t0     ; 158: and  v0,v0,t0      t0 = 0x00FFFFFF
138: or   v1,v1,v0     ; 160: or   v1,v1,v0
13c: sw   v1,0(a0)     ; 164: sw   v1,0(a1)
```

followed by the reverse direction into the table. The second `addPrim` reads
`getaddr(ot)` from the register the first one just stored there rather than
reloading it, so a recognizer that only looks for a `lw` misses half of it.
Anything short of both halves is reported as compatible/partial, never as the
macro.

## 4. The residual after the boundary was restored

With the operations in place the candidate is 105 instructions and the
rotation is gone. What is left is the birth order of the initializer calls.

The original session found the order by running all 24 permutations of the four
`POLY_F4` calls by hand. Re-derived from the header's verified field effects,
only 12 of those 24 are dependency-valid: `setPolyF4` writes `code` and
`setSemiTrans` reads and rewrites it, so `setSemiTrans` can never precede
`setPolyF4`. The other three pairs write disjoint named fields and commute.

Running the `sdk-call-order` transform template from a deliberately wrong
order reproduces the finding in one batch:

```
BYTE-EXACT CANDIDATE FOUND: p02
  basis: full-object — 105/105 instructions identical, relocations included
  expected .rtl: SDK call birth order setPolyF4 -> setRGB0 -> setXYWH -> setSemiTrans
```

The exact order is the natural one — initialize, colour, geometry, attribute —
which is the usual outcome once the operations are the SDK's rather than the
reconstruction's.

## 5. Hypotheses that were measured and rejected

**The flag hypothesis.** The target carries two symbolic lui/lw self-clobber
pairs, which is a real `-mno-split-addresses` fingerprint and fires the triage
detector:

```
lui $v1, %hi(D_8005E3C0)  /  lw $v1, %lo(D_8005E3C0)($v1)
lui $a2, %hi(D_8005E3B4)  /  lw $a2, %lo(D_8005E3B4)($a2)
```

The matrix on the matched source settles it:

```
baseline                  105/105 masked, 105 instrs
-mno-split-addresses       72/105 masked, 105 instrs
-fno-schedule-insns{,2}     2/105 masked, 111 instrs
```

Baseline beats every nominated column, so the conclusion is
`not-supported-current-source` — scoped to this source, which is the only scope
the measurement supports. The fingerprint remains a fact about the target; what
changes is that it is no longer the active remedy to chase. That distinction is
now cached in `build/flagProbe/<function>/report.json` and consumed by triage
under a function/source/target/toolchain hash check, so editing the source
invalidates the conclusion automatically.

**Compiler-state hypotheses generally.** Every one of them was reasoning about
where the compiler put instructions the source should not have been asking for.
The count delta was the tell: a macro expansion emits a different instruction
*set*, not a different order of the same one.

## 6. What changed in the tools

| gap | fix |
|---|---|
| exact-code-only primitive matching | attribute masks parsed from the header; composed codes recognized, unexplained bits refused |
| struct parser rejected fixed arrays | `u_long code[2]` modelled as aggregate plus addressable elements; `DR_MODE` is 12 bytes without restating it |
| one primitive per function | objects grouped by traced base-register web, so a reused hard register never merges two packets |
| "mask constant plus a store" hint | both halves of the link verified, including the CSE'd reload; partial merges reported as partial |
| SDK finding printed last | emitted first, ahead of inventory and allocation findings, with the reconstruct-before-tuning instruction |
| classifier had no SDK input | `SDK OPERATION-BOUNDARY CANDIDATE` section above the classification |
| adjacent macro calls not an axis | `sdk-call-order` stratum with publication barriers, recorded in `grammar.json`; `sdk-call-order` fuzz template as the direct fallback |
| exact variant buried under `inconclusive` | `BYTE-EXACT CANDIDATE FOUND` banner, orthogonal to the mechanism verdict |
| flag signal repeated after being measured | freshness-checked `report.json` consumed by triage |

## 7. The same shape is waiting elsewhere

Sweeping the fixed recognizer over the archived target assembly finds the
identical composed-code shape in an undecompiled function:

```
triage func_8001316C — target frame 0x0, source: stub
[signal] sdk-idiom
  target builds POLY_F4, DR_MODE through the configured PSY-Q SDK.
    58: sb v0,7(a3)   (code = 0x2A)
    observed code 0x2A = base 0x28 | setSemiTrans bit 0x2
```

That is a shared idiom, not TU evidence — same packet pair does not establish
same translation unit, and nothing here proves membership either way. It is
recorded because whoever picks up `func_8001316C` should start from the SDK
representation rather than rediscovering it, and because it shows the detector
now fires on a bare stub, before the first line of source exists.

## 8. Searchable signatures

- a code byte in no primitive table (`code 0x2A`) — strip the parsed attribute
  bits before concluding "not a primitive"
- `sb <len>, 3(base)` plus `sw <0xE1......>, 4(base)` — a `DR_MODE` command
  packet, not two anonymous stores
- `0xFF000000` and `0x00FFFFFF` masks around a word store — a manual `addPrim`
  tag merge
- an SDK-based candidate one instruction off with a broad register rotation —
  a missing macro operation, not an allocation problem
- SDK macro statement order — a bounded factorial axis, not a general search
