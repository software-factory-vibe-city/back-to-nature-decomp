# Retro: func_8001A574 — indirect-call arity, declaration shape, local allocation, and the last scheduler tie

**Final state:** clean C89, baseline flags, 61/61 instructions, exact relocated
bytes, and a byte-identical full executable payload. No register pinning,
embedded assembly, scheduling barrier, or flag override was used. The exact
function oracle and full build were verified independently. The aggregate
finalizer invocation remained blocked only by the unrelated pre-existing
`.pi/autoloop.json` modification, which was deliberately left untouched.

This was difficult because four different questions produced convincing versions
of the same symptom: wrong callback arity, wrong global declaration shape,
wrong local-allocation web population, and one final independent-instruction
scheduler tie. The exact source was found only after preserving gains from
lower-scoring mechanism experiments and inspecting the best pilot class from a
residual-source-space pricing run.

## Immediate replay checklist

For another function with an indirect call and a nearly exact instruction set:

1. **Prove callback arity from the candidate callees.** Registers `$a1`--`$a3`
   containing values at `jalr` are not automatically callback arguments; they
   may be stale caller-saved values, address-generation state, or values used
   in the call delay slot.
2. **Fix declarations before source-shape work.** Access width proves the field
   type, not the complete object's size. Address formation can prove that a
   symbol is an aggregate above the configured small-data threshold even when
   only offset zero is touched.
3. **Require final instruction count, empty inventory, and web parity before
   calling a residual allocation.** A register rotation before those gates is
   usually a semantic or declaration defect.
4. **Treat declaration initializers as executable birth sites.** C89 permits an
   initializer on a top-of-block declaration, and it can create a different
   RTL/source order from a later assignment.
5. **Test sequential role reuse, not only statement permutations.** Reusing one
   local for `product` and then `remainder` changed the allocator-visible web in
   the successful source; a fresh remainder local did not.
6. **Preserve partial mechanism wins.** One source family fixed `$a2/$a3` while
   worsening `$v0/$v1`. That was evidence, not a regression to discard.
7. **Price residual search, then inspect its best preserved pilot source.** A
   derive-only run compiles a bounded sample to estimate cost. Its best class
   can expose the missing source shape before exhaustive search starts.
8. **Run direct `diffFunc.ts --src` variants sequentially.** Parallel manual
   invocations share build paths and produced cross-contaminated outputs in
   this investigation. Use the isolated variant laboratory for concurrency.
9. **For the last order-only pair, name the value at the intended birth site.**
   Here a local loop sentinel born before the pointer assignment made the
   scheduler emit `li` before `move` with no extra instruction.

## 1. Recovered behavior

The function:

- divides `arg0` by three;
- uses the remainder to select one of three callbacks;
- passes only the quotient to that callback;
- computes a `u16` table position from `D_8005E4A8` and `D_8005E444`;
- scans forward to a `0xFFFF` terminator;
- shifts existing entries with `memmove`;
- copies generated entries from `D_8005F0F8` with `memcpy`; and
- restores the sentinel.

The decisive callback expression is:

```c
fn_result = (*entry)(quotient);
```

not a four-argument dispatch.

## 2. The first false premise: every live argument register was treated as an argument

The early candidate declared the dispatch table as callbacks taking four
arguments. That interpretation looked plausible at the indirect call because
`$a0`--`$a3` all held meaningful-looking values:

- `$a0`: quotient;
- `$a1`: dispatch-entry address;
- `$a2`: dispatch-table base;
- `$a3`: byte offset used to form the local table pointer.

Only `$a0` was a callback argument. `$a1` had already served as the address for
loading the function pointer, `$a2` was dead address state, and `$a3` was consumed
by the `jalr` delay-slot calculation. Inspecting the three dispatched callees
showed that each consumed one incoming `s32` and returned `s32`.

The four-argument prototype forced two compiled-only copies into the call setup
and produced 63 instructions. Correcting `FuncPtr_80049078` to one argument
removed those copies. The candidate then had the target's 61-instruction opcode
multiset and matching value-web population. That was the point at which
allocation and scheduling analysis became valid.

**General lesson:** reconstruct an indirect callback prototype from the callee
family, not from every caller-saved register that happens to contain a value at
`jalr`.

## 3. Declaration shape was part of instruction selection

Three declaration facts were required:

1. `D_8005E444` and `D_8005E4A8` are owned by this translation unit and need
   tentative definitions to reproduce GP-relative accesses.
2. `D_80049078` is a three-element function-pointer array whose callbacks take
   one `s32` and return `s32`.
3. `D_8005F0F8` is not a scalar merely because this function touches one
   halfword at offset zero. Declaring it as an aggregate larger than the active
   small-data threshold makes cc1 emit the target's split two-register absolute
   address form. A scalar declaration instead reaches a different compiler /
   assembler boundary and produces the wrong `$at`-macro form.

The maintained declaration belongs in `include/globals_override.h`; the
generated `include/globals.h` was regenerated from that input. The function
signature was exported through the context generator rather than hand-added to
the generated functions header.

**General lesson:** load/store width proves the accessed member width. It does
not prove the containing symbol's total declared size. Use the target address
formation as independent aggregate-size evidence.

## 4. The allocator problem after semantics were exact

After the arity correction, a natural one-argument source had the right
instructions and web parity but the wrong local colors:

| Role | Target | Natural candidate |
|---|---:|---:|
| division/quotient chain | `$v1` | `$v1` |
| initial sentinel | `$v0` | `$v0` |
| dispatch-table base | `$a2` | `$v0` |
| byte offset | `$a3` | `$a2` |
| active-table base load | `$v1` | `$v1` |

Only three encoded words differed, but simple declaration, expression, `% 3`,
`/ 3`, pointer, and statement-order variants normalized to the same compiler
state.

A second source family deliberately kept the quotient product live while the
dispatch base and offset were born. That fixed the `$a2/$a3` roles and the
entire target schedule, but swapped `$v0/$v1` across the division, sentinel, and
product chain. Its raw byte score was worse: eleven words differed. The lower
score nevertheless proved that the independent address/offset allocation was
reachable from clean C.

This is why match percentage could not be used as the experiment selector. The
source had solved one coupled mechanism while perturbing another.

## 5. The decisive source shape

`psx_search_residual_source_space` priced a domain of 110,936 candidates. Its
64-coordinate pilot sample preserved a best class under:

```text
build/residualSourceSearch/func_8001A574/a12033d8e98fcd0d/classes/c00026/source.c
```

That class was one scheduling pair from exact. Its important structure was:

```c
s32 quotient = arg0 / 3;
s32 product;
s32 offset;
FuncPtr_80049078 *base;
FuncPtr_80049078 *entry;

D_8005F0F8[0] = 0xFFFF;
offset = D_8005E444 * 2;
base = D_80049078;
product = quotient * 3;
p_table = (u16 *)((unsigned char *)D_8005E4A8 + offset);
product = arg0 - product;
entry = &base[product];
fn_result = (*entry)(quotient);
```

Three details were jointly load-bearing:

- `quotient` is initialized in its declaration, so the divide web is born
  before the first ordinary statement;
- the dispatch base, offset, product, and table pointer are born in the shown
  order; and
- `product` is overwritten with the remainder instead of introducing a fresh
  `remainder` local.

The resulting allocator state reproduced all target roles:

- quotient/division in `$v1`;
- sentinel and product/remainder temporaries in `$v0`;
- dispatch base in `$a2`;
- byte offset in `$a3`;
- dispatch entry in `$a1`; and
- final active-table pointer in `$s1`.

A less careful cleanup that extracts the declaration initializer into a later
assignment, adds a separate remainder local, or reorders the table-pointer
statement destroys that state while leaving the C semantics unchanged.

**General lesson:** in pre-SSA GCC, a declaration initializer and a sequentially
reused local are compiler-state inputs, not cosmetic style choices.

## 6. The final scheduling tie

The residual-search pilot source emitted the right instructions and registers
except for two independent loop-setup instructions:

```text
target:     li   a0,0xffff
            move v1,s1
candidate:  move v1,s1
            li   a0,0xffff
```

The source originally put the literal only in the `do/while` condition. Naming
it immediately before the pointer initialization changed its RTL birth site:

```c
if (*p_table != 0xFFFF) {
    sentinel = 0xFFFF;
    p_gap = p_table;
    do {
        gap_count++;
        p_gap++;
    } while (*p_gap != sentinel);
}
```

That produced the target order without a barrier or extra machine instruction.
The body statement order shown above was also retained.

**General lesson:** when a scheduler trace identifies a LUID/birth-site tie for
a constant and an independent copy, a named constant assigned at the intended
point is a narrow, natural source experiment.

## 7. What did not solve it

The investigation rejected or normalized away:

- the original four-argument callback hypothesis;
- `% 3` versus manual `arg0 - quotient * 3` alone;
- inline versus named quotient/remainder expressions alone;
- old-style or unprototyped callback declarations;
- raw pointer versus array indexing alone;
- argument reassignment and assignment expressions;
- simple declaration and statement permutations;
- separately named product, remainder, offset, and dispatch variables in the
  wrong birth order;
- named sentinel locals that accidentally stayed live across the callback and
  enlarged the frame;
- dead resets, self-assignments, compound assignments, and copy chains removed
  before local allocation; and
- flag hypotheses, which had no supporting target fingerprint.

Many visibly different C variants produced identical RTL or identical local
quantities. They were the same experiment and should not be counted separately.

## 8. Tooling lessons

### Inspect derive-only pilot classes

`deriveOnly` is not purely algebraic pricing. It compiles a sample to estimate
cost and records distinct classes. The best pilot source can be more useful than
the projected exhaustive domain. Here it exposed the exact declaration birth
and variable-reuse pattern, avoiding a 110,936-candidate full run.

Always read the pricing summary's best classes and directly run the configured
function oracle on their preserved `source.c` files.

### Do not parallelize manual `diffFunc --src`

Several manual `diffFunc.ts --src` commands were launched concurrently. They
shared build locations, and one result displayed another variant's frame and
register allocation. Critical candidates had to be rerun sequentially.

Use `psx_fuzz_variants` or the isolated source-search tools for parallel work.
If invoking the raw CLI against alternate sources, serialize the calls.

### A negative/search score is not the final oracle

The best residual class was summarized in the search comparison as 56/58
aligned compiler instructions and looked like it diverged at the indirect call.
The full configured diff showed 60/61 target words, with only the independent
loop-setup order remaining. Delay-slot alignment, assembler spelling, and each
tool's comparison basis differ. The promoted source was accepted only after the
exact relocated function diff and full binary check.

The final state passed:

- source-policy scan for the function;
- C source parsing/guard checks;
