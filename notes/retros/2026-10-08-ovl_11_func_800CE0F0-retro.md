# ovl_11_func_800CE0F0 — instruction birth, not register pinning

**Outcome:** integrated clean C matches 72/72 relocated words and passed the
full finalize gate. No register pinning, assembly, or new flag override was
needed. The verified source is `src/overlays/ovl_11/ovl_11_func_800CE0F0.c`
(SHA-256 `978af1a890169276b617e12ab9d7dd390368505ddf262d628ffc85b46d097383`).
This establishes a matching reconstruction, not the original author's exact C.

## 1. A missing copy need not be a coalesced source assignment

The indexed-state branch contains this target sequence:

```asm
sll  v1,a3,2
addu v0,a1,v1
move v1,v0
lh   s2,0x3D4(v0)
lh   s0,0x3D6(v1)
```

Ordinary pointer aliases (`ref2 = ref`) disappeared during early CSE. A prior
pipeline reading attributed the missing move to allocation coalescing, but its
machine-stage round-trip check failed. The candidate's earlier dumps did not
support treating that inferred copy origin as established.

The productive alternative was to express the two addresses through different
halfword/word unit conversions:

```c
offset = index * 4;
animation = ((s16 *)object)[offset / sizeof(s16) + 0x1EA];
frame = ((s16 *)((u32 *)object + offset / sizeof(u32)))[0x1EB];
```

These representations retained separate calculations until later simplification.
The subsequent reload CSE could replace a redundant address calculation with a
register copy. The compiler's `reload_cse_simplify_set` explicitly validates
replacing an expression with a hard register already holding its value.

**Transfer:** trace where an instruction is created or removed. Final machine
words alone do not distinguish an early copy retained through allocation from a
late arithmetic-to-copy rewrite. A bounded search over pointer aliases does not
close the unit-conversion family, much less all clean C. The eventual clean-C
match also makes the earlier register-pinning approval request obsolete.

Evidence: `build/declarationRepair/{continuity.txt,new-progress.txt,late-copy.c}`;
`prior-findings.txt` in that directory; the configured compiler's
`gcc/reload1.c`, `reload_cse_simplify_set`.

## 2. Variable history affects scheduling and allocation elsewhere

The successful source reuses `state` for the indexed offset in one branch and
for the embedded frame byte in the other, retaining `(s16)state` at the latter
use. It assigns `work` to the coordinate-buffer address after the branches,
then reuses it for the animation-advance mask.

Those histories mattered: branch-local buffer assignments, fresh aliases, and
other temporary-reuse sites did not produce the same schedule/allocation.
The scheduler trace explains one lever: its single-set birthing boost depends
on a pseudo's assignment count across the function, not just the current block.
Later simplification and allocation still have to be observed independently;
source assignment count is not a substitute for the compiler's actual state.

**Transfer:** make complete-function experiments about value definitions and
uses, rather than mechanically mapping each target register to a C local. The
winning reuse is a demonstrated compiler-state construction, not proof of the
original programmer's variable names or intent.

Evidence: `build/declarationRepair/{new-progress.txt,prior-scheduler.txt,
false-role-si.c,false-role-hi.c,negative-unit-views.c}` and the integrated C.
The saved progress notes predate the final match and are not current blockers.

## 3. Equivalent arithmetic can still differ by one encoded word

Both `false-role-si.c` and `false-role-hi.c` reached residual key `[0,0,0,0]`
but matched only 71/72 words. The remaining difference was the operand order of
an otherwise equivalent `addu`: target `v0,a1,v1`, candidate `v0,v1,a1`.
The negative-unit subtraction form in `negative-unit-views.c` fixed that final
word while preserving the useful late address simplification.

**Transfer:** the staged residual is useful for deciding which mechanism to
work on, but a zero key is not byte identity. Require the exact oracle before
promotion. Address-equivalence claims here are conditioned on the observed
callers' small index ranges; do not generalize them to arbitrary overflowing
signed arithmetic.

Evidence: `build/experimentLedger/ovl_11_func_800CE0F0.jsonl` records the two
71/72 results at 08:02:43 and the 72/72 result at 08:08:41 on 2026-10-08;
`build/pipelineReversal/ovl_11_func_800CE0F0/report.json` records the final match.

## 4. Repeated spellings were not independent experiments

Before parking, the ledger recorded **38 measurements but only 12 distinct
compiled-output hashes**. Much of the effort revisited the same compiler output
through different pointer/statement spellings.

**Transfer:** use output hashes to identify duplicates and pass traces to ask
whether a proposed edit reaches a different compiler state. Failed searches and
solver bounds must retain their source/domain premises; they are not evidence
that the original needs a forbidden construct.

## 5. Parking exposed a project-wide declaration contract

The failed attempt left `D_80128D00` overridden as a `u32[0xC]`, while the
already-matched `800CE5FC` declared it as `SpriteSourceData`. Restoring only the
`800CE0F0` assembly stub did not restore a coherent project, so the neighbor
failed to compile.

The repair used the actual shared sprite-source type in the override header,
tagged its existing struct for forward declaration through the include order,
and removed the neighbor's redundant declaration. `800CE5FC` remained 22/22.

**Transfer:** parking must leave shared declarations and matched neighbors
consistent, not merely restore one body. This suggests a transactional parking
regression test; the copy-origin and zero-residual/nonexact cases also deserve
diagnostic regressions. Those tooling changes have not been implemented here.
