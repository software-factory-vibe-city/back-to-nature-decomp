# Retro: func_80022738 — 20 instructions, stuck at 90%, and the two prototypes that weren't there

Final state: byte-verified match (20/20, `VERIFIED` on the linked binary,
`make check` OK), clean C89, baseline flags, no policy exceptions. The
entire fix relative to the stuck state: delete the `do { } while (0)`
fence, delete its justifying comment, add two `void` prototypes:

```c
void SetVal8005E2BC(s32); /* extern */
void SetVal8005E334(s32); /* extern */
```

The function is a state-flag check/advance: read a byte at
`D_8006C838+0xCC`, and if it is 4, write 5 and set two gp-relative
globals. No loop, one branch. It consumed a multi-session investigation
that produced a 15-variant source search, an allocator counterfactual, a
flag probe, a target-schedule replay, and a parked comment concluding "no
identified clean-C lever."

## 1. The actual mechanism

The stuck TU declared no callees. `common.h` provides types and globals
but no function declarations, and the parked source declared none
locally. Under C89 both `SetVal8005E2BC(1)` and `SetVal8005E334(1)` were
implicit-int calls, so each expanded as `(set (reg v0) (call …))` — a
dead `$v0` definition at every call site.

Local allocation never gave `$v0` to anything born between the last call
and the next explicit `$v0` write. The instrumented oracle
(`instrumentCompilerOracle` + `analyzeLocalAllocationOracle`, stock
replay 5/5) showed hard register 2 "excluded from every stock
find_free_reg candidate list" for both the hi16 quantity and the byte
quantity. The target needs `lui $v0` — so **every variant was fighting an
allocator whose `$v0` was poisoned before the first line of the function
body was written**. That is why 15+ shape variants "all diverge at the
same lui": they shared the defect, which was not in the shapes.

With the two `void` prototypes, the calls stop defining `$v0` and stock
allocation produces the target coloring deterministically, with no other
source change:

- hi16 (block-local, dies at the `addiu`) → `$v0`
- const 4 (block-local, disjoint) → shares `$v0`
- byte (block-local) → `$v1`
- `p` (cross-block, global-allocated): prefers hi16's `$v0` because hi16
  dies into its def, but `$v0` conflicts with the consts and `$v1` with
  the byte → falls to allocation order → `$a0`, sourcing the `addiu` from
  `$v0`. The "uncoalescible hi16" the parked comment searched for is just
  a preference that loses to a conflict.

Both callees were already matched in this repo as `void` functions
(`src/SetVal8005E2BC.c`, `src/SetVal8005E334.c`), and
`include/functions.h` already carried the correct declarations. The
information existed in three places; the TU saw none of them.

## 2. What the fence was actually doing

The parked comment claimed the fence was "required to force the pointer
into $a0". Controlled A/B on the reconstructed stuck source (fence vs
no-fence, both still implicit-int) confirms the observation: with fence
18/20 (`p`=$a0, byte=$v1), without 15/20 (`p`=$v1, byte=$a0). Same
instruction structure both ways; a pure allocation rotation. The style
guide at the time listed `do { } while (0)` fences under "codegen no-ops
(do not waste turns)" — the working tree and the doctrine flatly
contradicted each other, and no session reconciled them. The mechanism is
loop-depth reference weighting: a degenerate loop scales the ref counts
of everything inside it and reorders quantity priorities.

So the fence bought +3 score by rotating two of the three wrongly-colored
webs into place — an allocation coincidence layered on the real defect,
purchased with a construct the original programmer had no reason to
write. It also anchored the investigation to allocator internals
("coalescing", "web structure") when the residual's true cause was a
missing declaration.

## 3. A second trap, stepped in live while writing this retro

Mid-session, `src/func_80022738.c` changed on disk to a third variant —
the inline constant-address form
`*(u8 *)((char *)&D_8006C838 + 0xCC)` with no pointer variable. Analysis
artifacts from that variant (a 19-instruction fold, front-end address
folding, a web-parity failure) were briefly attributed to the fence
version, producing a wrong causal story that survived until the
pre-writeup verification pass re-ran every pipeline from reconstructed
sources. Two lessons, both already in doctrine but evidently needing
teeth:

- **Provenance before comparison.** An artifact is evidence about the
  exact preprocessed input and flag set that produced it, nothing else.
  Same function name ≠ same source. (The stale-artifact rule generalizes:
  it is not only *stale* artifacts that mislead, but *sibling* ones.)
- The inline-constant form is itself a real finding: the front end folds
  `&SYM + const` per use — offset into the reloc, no `addiu`, no shared
  base web. Structurally unreachable from a target that materializes a
  reusable base register. Now a style-guide bullet.

## 4. Why the agent couldn't get it (ranked)

1. **Undeclared callees are invisible to the loop.** Triage checks the
   frame, idioms, inventory, arity, and flags of *the target function*;
   nothing checks that every called symbol has an evidence-consistent
   declaration in scope. The defect predates the first source line and no
   amount of downstream analysis (all of which correctly explained the
   wrong world) can see it.
2. **An impossible register is a symptom class, and it went unread.**
   Across 15+ variants, hi16 landed in `$v1` or `$a0` — never `$v0`, the
   register the target uses. "A register the target uses is never
   produced by any variant" should route to *what is occupying it*, i.e.
   to context outside the function body, not to more shapes.
3. **The target already proved the signatures.** `li v0,4` three
   instructions after a `jal` means the callee's return value — if any —
   is dead; two calls followed immediately by `$v0` scratch use is
   positive evidence of `void` callees. Reading the callee's own matched
   source (one `grep`) would have settled it. The call-graph entry names
   the callees; their sources were matched months ago.
4. **Doctrine and working tree contradicted each other silently.** The
   style guide said fences do nothing; the parked comment said the fence
   was load-bearing. Both cannot be true, and whichever session first
   observed the contradiction owed the project a correction or a filed
   objection. Instead the contradiction persisted and misled both
   directions: the guide told agents not to investigate fences, the tree
   taught agents to use them.
5. **Effort substituted for premise-checking.** The parked comment's
   tested-list is genuinely impressive — residual search, counterfactual,
   flag probe, schedule replay — and every item of it ran downstream of
   an unexamined premise. The loop's own doctrine ("a wrong structural
   premise cannot be recovered by scheduling or allocation work
   downstream") applied, but "structural" was read as
   *statements-in-this-function*, not *the TU the function compiles in*.

## 6. Recommendations (owner decisions, not made unilaterally)

1. **Triage detector, blocker class: undeclared callee.** ~~Cheap to
   implement; high yield.~~ **Implemented 2026-08-06** (owner-approved):
   `detectImplicitDeclarations` in `tools/agent/decompToolchain.ts` re-runs
   cc1 on the preprocessed TU with `-Wimplicit`; triage surfaces the
   warnings as the `undeclared-callee` blocker, printing the known-good
   declaration from `include/functions.h` when one exists. Verified: fires
   on the reconstructed stuck state, silent on the fixed source and on
   sampled matched functions; parser unit-tested.

   A same-day sweep of all 172 matched C sources found 3 files with
   undeclared callees that byte-match anyway: `func_800129F4.c`
   (`SetDispMask`), `func_80015704.c` (`FntPrint`, `func_800129E8`,
   `func_80015880`), `func_800179E8.c` (`ClearVal8005E4B0`). Left as-is
   deliberately: for a *matched* TU, implicit declarations may be the
   original file's true state (period code routinely omitted them), and
   adding a declaration can change allocation. If a refinement pass takes
   these up, re-verify per file — and treat "declaring it breaks the
   match" as TU-state evidence, not a failure.
2. **Declaration sourcing convention.** Matched sources currently
   re-declare callees by hand (`/* extern */` lines). That convention
   worked everywhere it was followed; the failure was following it
   nowhere in this TU. Either enforce it (detector above) or have the
   context exporter emit the known-good declarations for a target's
   callees from `include/functions.h` when a session opens a function.
3. **Cross-tool count disagreement as an explicit alarm.** `diffFunc`
   (post-assembler bytes) and `explainDiff` (cc1-level) can legitimately
   disagree about instruction count for reloc-folded forms; when they do,
   the delta is assembler-layer rewriting and compiler-level causal
   claims about it are out of bounds. A one-line warning in either tool
   when counts differ for the same source would have shortened both the
   original investigation and this session's own detour.
