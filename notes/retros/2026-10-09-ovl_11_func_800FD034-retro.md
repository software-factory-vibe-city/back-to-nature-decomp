# ovl_11_func_800FD034 — two facts the residual could not show

**Outcome:** clean C matches all 88 words, with no flag override. The finalize
gate passes: exact diff, linked build, scope and clean-source.
- Source: `src/overlays/ovl_11/ovl_11_func_800FD034.c`.
- `include/globals_override.h` declares `D_80127210` as `s16`, so the source
  needs no casts.

The autoloop (deepseek-v4-1-flash) worked it for 37 minutes and parked it at
78/83 words. Its best on disk was 81/89. The function is a scrolling list: it
moves a signed top row with the input bits, wraps it, draws two arrows, and
calls a row-drawing callback for seven rows.

## The two facts

**1. The counter is an `int` assigned by three separate statements.**

```c
i += 1;
i <<= 16;
i >>= 16;
draw(i, y);
y += 0x18;
```

The target's angle register starts at 0x480000 and steps by 0x180000. That is
exactly the giv that `loop.c` builds for `y << 16` when `y` is an `s16` advanced
by `y += 0x18`: (0x30 + 0x18) << 16. So strength reduction was on in the
original build, and the angle source is the natural increment.

The counter is not reduced in the target, so it cannot be a basic induction
variable. `basic_induction_var` follows a sign extension through an
`ashiftrt` of an `ashift`. A set of the variable by a bare `ashift` falls to
`default` and returns 0. Every spelling of the counter as `s16`, or as an
`int` with a `(s16)` cast, expands through `extendhisi2`. That expander emits a
fresh temporary for the left shift, so the counter stays a biv and gets
reduced. Separate `<<=` and `>>=` statements set the counter itself. The
counter stops being a biv, so it is never reduced. All three instructions land
in place on `$s0`, as in the target.

**2. The callback is copied into a local in the body.**

```c
draw = arg1;
```

With that fixed, the prologue still placed `move $s4,$a1` above the `arg0`
extension. In the first scheduling pass, all three instructions are promoted, so
the tie goes to original stream position. `assign_parms` emits parameter
conversions after all parameter copies, so the `arg0` extension is later in
the stream than the callback copy. It wins, and the copy drifts up. A body
statement `draw = arg1` puts the copy after the conversion, and it sinks below
the extension, as in the target.

Both facts are load-bearing. `i = (i + 1) << 16 >> 16` and `i = (s16)(i + 1)`
fall back to a reduced counter at 57/87. Removing the local copy reopens the
prologue schedule difference.

## Why it was difficult

- **The session wrote the optimizer's output as source.** It typed m2c's
  accumulator literally (`var_s1 = 0x480000; ... var_s1 += 0x180000`), because
  the matched neighbour `ovl_11_func_800FC8C8` has that shape. It reasoned
  `angle += 0x18` away as "compiler would emit addiu" and never compiled it. The
  literal accumulator hid the evidence that strength reduction was on.
- **It concluded strength reduction was the enemy, then turned it off.** It saw
  the counter get reduced, and added `-fno-strength-reduce` to
  `configs/flag_overrides.mk` without a fingerprint. Its measurements for a
  stretch were taken under a compiler the target did not use. It reverted the
  flag before parking.
- **It read a population fact as an allocation problem.** The out-of-place
  `sll $v0,$s0,16` exists only because of the extend expander's temporary. The
  session spent most of the run on allocator tools and variable-sharing
  spellings to coax that temporary into `$s0`. It read `extendhisi2`, saw the
  temporary was unconditional, and decided the original might have used a
  different compiler. It never read `basic_induction_var` to ask what keeps a
  counter out of strength reduction.
- **The prologue fact was never reached.** The loop dominated the residual, so
  the two-instruction schedule difference in the first block was never worked.
- **Discipline collapsed.** The session made 175 bash calls on this function
  against 8 `psx_residual_objective` calls. It edited `src/` with sed and
  python, and ended by scanning every object file in `build/` for an in-place
  extend.

## How it was found

1. A `psx_loop_trace` of the natural form showed the angle giv reduced to an
   initial value of 0x480000, which is the target's value. The counter giv was
   reduced too, and the target's is not.
2. `basic_induction_var` named what stops a variable from being a biv: a set it
   cannot classify. The first batch with shift statements cleared every loop
   block.
3. `psx_scheduler_trace` on the first block showed a position tie, and
   `assign_parms` explained the position. A local copy was the first
   experiment, and it matched.

**Transfer:**
- A loop accumulator that starts at the second value, shifted, is a reduced
  giv. Write the natural increment and let the loop pass build it.
- When a target leaves one induction variable unreduced and reduces another,
  the unreduced one is set by something `basic_induction_var` rejects. Find
  that set in the source; do not turn the pass off.
- A cast or a short type always sign-extends through a fresh temporary. An
  extension done in place on the variable is separate shift statements.
- Parameter conversions are emitted after every parameter copy. A copy that
  must sit below a conversion is a body statement.
